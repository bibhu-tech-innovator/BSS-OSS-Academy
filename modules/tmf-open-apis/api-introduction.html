Introduction to TM Forum Open APIs

What TM Forum Open APIs are, why they exist, RESTful design principles, and the overall API landscape.

What Are TM Forum Open APIs?

TM Forum Open APIs are a suite of standardised RESTful APIs that define how BSS/OSS components should communicate with each other. They are the concrete realisation of TM Forum's Open Digital Architecture (ODA) principle of componentisation — breaking monolithic BSS/OSS systems into loosely coupled, API-connected components that can be mixed, matched, and replaced independently.

Each API is defined by:

  • A RESTful interface — Standard HTTP methods (GET, POST, PUT, PATCH, DELETE) with JSON payloads.
  • A canonical data model — Aligned to the SID (Information Framework), ensuring consistent entity definitions across all APIs.
  • Query and pagination patterns — Standardised filtering, sorting, and pagination parameters.
  • Notification model — Standard event-driven notifications for state changes (e.g., order state change notification, product creation event).
  • Contract-first specification — Each API is published as an OpenAPI 3.0 specification, enabling contract-first development and automated client generation.

Why Do They Exist?

Historically, every BSS/OSS vendor exposed proprietary APIs. Integrating a new system required building custom adapters for each vendor interface — expensive, brittle, and slow. TM Forum Open APIs solve this by providing a standard integration contract that all vendors can implement. The benefits include:

  • Reduced integration cost — Standard APIs replace custom adapters. A mediation engine that speaks TMF 639 (Resource Inventory) can connect to any inventory system that also implements TMF 639.
  • Vendor independence — If a vendor's pricing or features become uncompetitive, their component can be replaced by another vendor implementing the same TMF API without rebuilding all integrations.
  • Accelerated digital transformation — New capabilities (AI-based assurance, digital wallet, partner management) can be integrated via standard APIs rather than custom point-to-point interfaces.
  • ODA compliance — TM Forum Open APIs are the integration backbone of the Open Digital Architecture. ODA-compliant systems are expected to expose TMF APIs.

RESTful Principles

TM Forum APIs follow standard RESTful design principles:

  • Resource orientation — Each API manages a set of resources (ProductOffering, Order, Bill, Resource) identified by unique IDs and accessed via URL paths.
  • CRUD operations — Standard HTTP verbs map to lifecycle operations: GET (retrieve), POST (create), PUT/PATCH (update), DELETE (remove).
  • HATEOAS — Responses include hypermedia links to related resources, enabling API discoverability.
  • Idempotency — PUT and DELETE operations are idempotent; POST for creation may include idempotency keys to prevent duplicate resource creation.
  • Versioning — APIs are versioned (v1, v2, v3...) to enable non-breaking evolution. Clients specify the version in the URL or Accept header.

The TMF API Landscape

TM Forum has published over 60 Open APIs covering the full BSS/OSS spectrum. They are grouped into functional domains:

DomainKey APIsPurpose
Product & CatalogTMF 620, TMF 622, TMF 633Product catalog management, product offering qualification, service catalog management
Ordering & FulfilmentTMF 641, TMF 652, TMF 622Service order management, resource order management, product order management
InventoryTMF 637, TMF 638, TMF 639Product inventory, resource catalog, resource inventory management
AssuranceTMF 642, TMF 655, TMF 656Alarm management, service test management, performance monitoring
BillingTMF 678, TMF 648, TMF 445Customer bill management, usage consumption management, party bill management
Party ManagementTMF 629, TMF 632, TMF 666Customer management, party management, account management

The APIs are designed to work together. A typical flow might involve TMF 622 (Product Order) triggering TMF 641 (Service Order), which in turn invokes TMF 652 (Resource Order) to activate a service via network elements.

Key Takeaways

  • TM Forum Open APIs are standardised RESTful interfaces with canonical SID-aligned data models, enabling plug-and-play integration.
  • They reduce integration cost, enable vendor independence, and are the foundation of ODA compliance.
  • Over 60 APIs exist across catalog, ordering, inventory, assurance, billing, and party management domains.
  • APIs are designed to work in concert, with each step in the L2C chain invoking downstream APIs via standard contracts.
