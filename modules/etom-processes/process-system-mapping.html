Process-to-System Mapping

Coverage matrices, gap analysis, and system ownership assessment

Process-to-System mapping is a critical architecture analysis technique. It answers the question: "Which systems support which business processes?" The resulting coverage matrix reveals gaps, overlaps, and single points of failure in the application portfolio.

Process-to-System Coverage Matrix

The matrix below maps common L2 eTOM processes to typical BSS/OSS systems. A filled cell indicates a system plays a role in that process. The matrix helps identify:

  • Gaps — Processes with no system support (manual or missing).
  • Overlaps — Multiple systems claiming the same process (duplication).
  • Critical systems — Systems involved in many processes (high dependency risk).

Gap Analysis Process

Performing a gap analysis using this mapping involves the following steps:

  1. List all relevant eTOM L2/L3 processes for the scope of the assessment.
  2. Map each process to the system(s) that currently support it.
  3. Rate the coverage level — Full (automated), Partial (semi-automated), Manual, None.
  4. Highlight gaps — Manual or None coverage indicates a process gap.
  5. Highlight overlaps — Two or more systems providing full coverage for the same process may indicate redundancy.
  6. Prioritise — Gaps in revenue-critical processes (e.g., Order Handling) are higher priority than gaps in support processes.

Common Patterns in Telco Coverage Matrices

  • CRM sprawl — CRM often ends up supporting processes it was not designed for (e.g., quoting, order validation, service configuration). This is a sign of missing CPQ and SOM capabilities.
  • Billing as order system — Some operators use billing as the order capture system, leading to data duplication and reconciliation issues.
  • Assurance disconnected from fulfilment — Service assurance systems often have no visibility into what was ordered or activated, making fault correlation difficult.
  • Multiple single-purpose tools — Instead of a SOM, operators may have separate tools for order decomposition, service design, and resource assignment, creating manual handoffs.

Key Takeaway

Process-to-system mapping is not a one-time exercise — it should be maintained as the system landscape evolves. The coverage matrix is a powerful communication tool between business and IT teams, making visible where automation investments are needed and where system rationalisation can reduce operational cost and complexity.
