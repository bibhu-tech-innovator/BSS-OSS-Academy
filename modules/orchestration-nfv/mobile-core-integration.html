Mobile Core Integration

4G/5GC, MANO, network slicing, and NFVI

The mobile core domain presents a different integration challenge than IP/MPLS. Mobile core functions (4G EPC, 5GC) are increasingly virtualised (VNFs/CNFs) and managed by MANO platforms. Integration here involves not just device configuration but lifecycle management of virtual network functions.

Mobile Core Architecture Overview

GenerationCore ComponentsVirtualisationOrchestration
4G / LTEMME, SGW, PGW, HSS, PCRFVNF (virtualised network function)NFV Orchestrator (NFVO), VNF Manager (VNFM)
5G (Standalone)AMF, SMF, UPF, UDM, AUSF, PCF, NRF, NSSFCNF (cloud-native network function)Kubernetes-based, MANO with CNF support

MANO (Management and Orchestration) Framework

ETSI NFV MANO is the standard framework for managing VNFs and CNFs. It defines three functional blocks:

  • NFVO (NFV Orchestrator) — Orchestrates NFVI resources, manages network service lifecycle (instantiate, scale, terminate).
  • VNFM (VNF Manager) — Lifecycle management of individual VNF instances (deploy, configure, monitor, heal).
  • VIM (Virtualised Infrastructure Manager) — Manages compute, storage, and network resources (OpenStack, VMware, Kubernetes).

Network Slicing

Network slicing (5G) allows multiple logical networks (slices) to run on the same physical infrastructure. Each slice is an end-to-end logical network optimised for a specific service type:

Slice TypeUse CaseCharacteristics
eMBBEnhanced Mobile BroadbandHigh bandwidth, moderate latency
URLLCUltra-Reliable Low-Latency CommunicationsLow latency (1ms), high reliability
mMTCMassive Machine-Type CommunicationsHigh device density, low bandwidth

From an OSS perspective, network slicing requires the XDO/MANO to be able to: create a slice instance, assign network functions to the slice, configure slice-specific policies (QoS, routing), and monitor slice-level KPIs.

Worked Example: 5G Slice for Enterprise Service

StepActionSystem
1Enterprise customer orders "5G Private Network with Slice"CRM / CPQ
2COM creates commercial order, SOM decomposes to RFS for mobile core + transportCOM → SOM
3XDO requests transport L3VPN from NSO and 5G slice from NFVOXDO → NSO, XDO → NFVO
4NFVO instantiates UPF, SMF, AMF instances for the enterprise sliceNFVO → VIM (Kubernetes)
5VNFM configures UPF with customer-specific routing and QoS policiesVNFM → UPF (NETCONF)

7SOM notifies COM and billing system to start chargingSOM → Billing

Key Takeaway

The mobile core domain introduces a new dimension to OSS orchestration: lifecycle management of virtualised functions, not just device configuration. The XDO must integrate with MANO platforms (NFVO, VNFM) in addition to domain controllers like NSO. Network slicing further increases complexity by requiring the XDO to manage slice instances as a new type of resource. The key principle is that the XDO should treat the MANO platform as just another domain controller — it sends resource intents ("create slice for customer X") and receives status responses, without needing to understand the details of VNF instantiation.
