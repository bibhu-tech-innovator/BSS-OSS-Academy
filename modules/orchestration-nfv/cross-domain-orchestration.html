OSS Functional Layering & Cross-Domain Orchestration

Strict layering between CRM/CPQ, COM/SOM, XDO, and ROM/domain controllers

Multi-domain orchestration is the most architecturally complex part of OSS. It requires strict layering to manage the translation from commercial intent to network configuration across heterogeneous domains. This section establishes the canonical layering model.

Product-to-Network Mapping

The journey from a product to network configuration follows a strict decomposition chain:

Product Offering (Catalog) → Product Spec (CFS) — "Business Internet 100Mbps" → CFS Spec — "Managed IP VPN with QoS" → RFS Spec — "L3VPN VRF + BGP peering" → Resource Spec — "VLAN 100, IP 10.1.1.1/30, QoS profile Gold" → Device Config — "set interfaces ge-0/0/1 vlan-id 100"

Why Strict Layering Matters

Without strict layering, each system touches every other system. The result is a "spaghetti" integration architecture where a change in one system has unpredictable impacts. Strict layering enforces that:

  • CRM/CPQ only speaks to COM (not to SOM, XDO, or domain controllers).
  • COM only speaks to SOM (not to XDO or domain controllers).
  • SOM only speaks to XDO (not to domain controllers directly).
  • XDO only speaks to domain controllers (not to SOM or COM).
  • Each layer translates from the language of the layer above to the language of the layer below.

Cross-Domain Orchestrator (XDO) Responsibilities

The XDO is the brain of the OSS fulfilment layer. Its key functions:

  • Resource intent decomposition — Break a resource order into domain-specific resource requests.
  • Sequencing — Determine the correct order of operations (e.g., provision IP transport before mobile core).
  • Domain assignment — Route each resource request to the appropriate domain controller.
  • State aggregation — Aggregate domain-level status back into service-level status.
  • Error handling — Coordinate rollback or compensation when a domain operation fails.

Example: Multi-Domain Order Flow

StepLayerAction
1CRMCustomer orders "Business MPLS Bundle" (VPN + Internet)
2COMValidates, creates commercial order, decomposes to service orders
3SOMDesigns CFS (Managed VPN), identifies RFS (L3VPN, Internet Access)
4XDOSends L3VPN config to NSO (IP domain), Internet config to BNG controller
5ROMNSO pushes NETCONF to PE routers; BNG controller configures BRAS
6XDOAggregates success from both domains, reports to SOM
7BillingNotified post-activation to start recurring charges

Key Takeaway

Strict layering is the single most important architectural principle in multi-domain orchestration. Each layer translates and abstracts — never bypasses. The XDO is not optional; it is the essential integration point that prevents domain knowledge from leaking into service management, and service logic from leaking into domain controllers. Without it, you end up with domain-specific logic in your SOM and service logic in your domain controllers, which makes both layers impossible to evolve independently.
