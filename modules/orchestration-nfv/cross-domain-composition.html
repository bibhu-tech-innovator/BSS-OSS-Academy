11.6 Cross-Domain Composition: Worked Examples

Enterprise SD-WAN, 5G URLLC, FTTH, and Enterprise Ethernet

Cross-domain orchestration becomes concrete when applied to real services. Each use case below shows how the orchestrator decomposes a service order into domain-specific resource orders across multiple network domains.

Enterprise SD-WAN

Service description: A multi-site enterprise SD-WAN service connecting 10 branch offices to a central data centre with application-aware routing and encryption.

Domains involved:

  • CPE domain: Provision SD-WAN edge devices at each site (uCPE or vCPE) — zero-touch provisioning via TR-069/USP.
  • IP/MPLS domain: Set up L3VPN or L2VPN connectivity from each branch to the hub. Provision QoS profiles for real-time traffic.
  • Transport domain: For sites using dedicated fibre, provision the last-mile access circuit between the CPE and the PE router.
  • SD-WAN controller: Configure the overlay — tunnel endpoints, steering policies, application classification, and SLA thresholds.

Orchestration flow: The XDO receives the SD-WAN service order and creates parallel resource orders for each domain. The CPE must be online before the SD-WAN controller can configure the overlay. The IP/MPLS circuits must be active before the edge devices can establish tunnels. The XDO manages these dependencies using a topological decomposition plan from the Service Catalog.

5G URLLC — Ultra-Reliable Low-Latency Communication

Service description: A factory automation slice requiring sub-10ms latency, 99.999% reliability, and guaranteed bandwidth for robot control traffic.

Domains involved:

  • Mobile core (5GC): Create a network slice with dedicated UPF (User Plane Function) for the factory traffic. Configure NSSF, SMF, and UPF for the slice.
  • RAN domain: Configure gNB (5G base station) with appropriate radio parameters — numerology, slot format, and resource partitioning for URLLC.
  • Transport domain: Provision dedicated transport with deterministic latency and low-jitter characteristics between the gNB and the UPF.
  • NFVI domain: Ensure the UPF is deployed on a compute node with real-time kernel, SR-IOV NIC, and strict CPU pinning.

Orchestration flow: The URLLC slice order is decomposed into parallel and sequential activities. NFVI resources must be provisioned before the UPF can be instantiated. The transport circuit must be active before the slice can be activated. The RAN configuration depends on the slice ID allocated by the 5GC.

FTTH — Fibre to the Home

Service description: A residential FTTH broadband service (as worked in Section 2.4). This is the most common cross-domain service in fixed access.

Domains involved:

  • PON access domain: Provision the OLT port, bind the ONT, configure the service VLAN and bandwidth profile.
  • IP/MPLS domain: Configure the BNG subscriber session, apply QoS policy, and enable routing to the internet or VPLS.
  • CPE domain: Push Wi-Fi and VoIP configuration to the home gateway via TR-069.
  • IPAM domain: Allocate a public IP address and VLAN ID from the management system.

Orchestration flow: The XDO coordinates the domains in a specific sequence — IPAM reservation first, then PON provisioning, then BNG configuration, and finally CPE configuration. Each step depends on outputs from the previous step (e.g., the VLAN ID from IPAM is used in both PON and BNG configurations).

Enterprise Ethernet

Service description: A 1 Gbps point-to-point Ethernet private line between two office locations with MEF-compliant service attributes.

Domains involved:

  • Access domain: Provision the NID (Network Interface Device) at each site. Configure the UNI (User Network Interface) parameters — speed, MTU, VLAN handling.
  • Transport domain: Provision the underlying transport circuit (e.g., MPLS-TP or OTN) between the two PE nodes.
  • IP/MPLS domain: Configure EVPN or VPWS for the Ethernet virtual circuit between the two sites.
  • Service assurance domain: Set up active performance monitoring (Y.1731, TWAMP) for SLA verification on the EVC.

Orchestration flow: The XDO decomposes the Ethernet service into two UNI configurations and one EVC configuration. The UNIs are provisioned first (at each site independently), then the EVC is stitched across the transport network. Performance monitoring is enabled after the EVC is active.

Use Case Domains Key Coordinator
Enterprise SD-WAN CPE, IP/MPLS, Transport, SD-WAN Controller Overlay tunnel lifecycle
5G URLLC Slice 5GC, RAN, Transport, NFVI Slice ID and QoS flow mapping
FTTH Broadband PON, IP/MPLS (BNG), CPE, IPAM VLAN ID and IP address linkage
Enterprise Ethernet Access (NID), Transport, IP/MPLS, Assurance EVC ID and UNI configuration

Key insight: All four examples share a common pattern: the XDO receives a service intent, decomposes it into domain-specific resource orders, manages dependencies between domains, and stitches the domain outputs into a coherent end-to-end service instance. The catalog-driven decomposition rules determine which domains are involved and in what order they must execute.

Key Takeaways

Key Takeaways

  • Enterprise SD-WAN involves CPE, IP/MPLS, transport, and SD-WAN controller domains working together to create an overlay network.
  • 5G URLLC slices require coordination of mobile core, RAN, transport, and NFVI domains for deterministic low-latency service.
  • FTTH broadband is the most common cross-domain service — PON, BNG, CPE, and IPAM must execute in dependency order.
  • Enterprise Ethernet combines access, transport, and IP/MPLS domains to deliver carrier-grade private line services.
  • The cross-domain orchestrator manages dependency ordering and parameter stitching across all involved domains for every service type.
