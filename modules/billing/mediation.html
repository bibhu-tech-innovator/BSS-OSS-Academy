Mediation & CDR Processing

How raw network usage data is collected, normalised, correlated, enriched, and distributed for rating and billing.

The Mediation Layer

Mediation sits between the network and the billing system. Its job is to collect raw usage data — in various formats, from various network elements — and transform it into a standardised, correlated, and validated set of Charging Data Records (CDRs) suitable for rating and invoicing. Mediation is a critical control point for revenue assurance: if mediation loses data or introduces errors, revenue leaks.

The Mediation Pipeline

A typical mediation pipeline processes CDRs through four stages:

StageDescriptionCommon Issues
1. CollectionRaw usage records are collected from network elements — SGSNs, GGSNs, MSC, S-CSCF, P-GW, SBC, BRAS. Methods include FTP/SFTP file pull, Diameter Rf streaming, Kafka event bus, and API polling.File delays, missing files, duplicate delivery, format changes
2. NormalisationRaw records are parsed from vendor-specific formats (ASN.1, BER, text-based, proprietary binary) into a standard internal CDR format with consistent field names, data types, and units.Vendor format changes, invalid field values, encoding mismatches
3. CorrelationPartial CDRs from different network elements are correlated into a single complete service event. For example, one voice call generates CDRs from the calling party's MSC, the called party's MSC, and the GMSC — these must be correlated to avoid double-charging.Timing skew between network elements, partial correlations, orphan CDRs
4. EnrichmentCorrelated CDRs are enriched with additional data from external sources: subscriber plan information for rating, location data for roaming determination, number portability status, and tax jurisdiction mapping.Lookup latency, stale reference data, incomplete enrichment

CDR Types

Different network domains produce different types of usage records:

  • Call Detail Records (CDRs) — Traditional voice call records from circuit-switched networks (MSC, GMSC, TMSC). Contain calling/called numbers, duration, start time, and cause for termination.
  • Session Detail Records (SDRs) — IMS session records from SIP networks. Cover voice, video, and messaging sessions over LTE/VoLTE.
  • Data Detail Records (DDRs) — Data session records from packet-switched networks (GGSN, P-GW). Contain volume (uplink/downlink), duration, APN, QoS class, and IP address.
  • Service Detail Records (SDRs) — Value-added service records (content purchases, application usage, messaging).
  • Event Detail Records (EDRs) — Generic event records for non-session-based usage (SMS, MMS, top-ups, feature activations).

Validation and Error Handling

Mediation systems apply rigorous validation rules at each stage of the pipeline:

  • Format validation — Are all required fields present? Are numeric fields valid numbers? Are date/time fields parsable?
  • Range validation — Is the call duration reasonable? Is the data volume within limits?
  • Duplicate detection — Records with identical key fields (calling number, timestamp, call ID) within a time window are flagged as potential duplicates.
  • Orphan handling — Partial CDRs that cannot be correlated are held in an exception queue for manual processing.
  • Threshold alerts — Sudden drops or spikes in CDR volume trigger alerts for revenue assurance investigation.

Distribution and Downstream Systems

After mediation, validated and enriched CDRs are distributed to downstream systems:

  • Rating Engine — for usage rating and charge calculation.
  • Interconnect Settlement — for partner settlement of off-net traffic.
  • Revenue Assurance — for independent verification of the mediation pipeline.
  • Data Warehousing / Analytics — for usage trend analysis, capacity planning, and marketing insights.
  • Fraud Management — for real-time and post-event fraud detection based on usage patterns.

Key Takeaways

  • Mediation is the critical pipeline between network elements and billing systems, handling collection, normalisation, correlation, and enrichment.
  • CDRs vary by domain: voice (CDR), IMS session (SDR), data session (DDR), and events (EDR).
  • Validation and error handling are essential to prevent revenue leakage from lost, duplicated, or malformed CDRs.
  • Distribution extends beyond billing to interconnect, revenue assurance, analytics, and fraud management.
