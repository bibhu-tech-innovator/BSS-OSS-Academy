Section 2.4

Worked Example: Connectivity Service

A complete worked example showing how a broadband product decomposes through all catalog layers

Let's bring all the catalog concepts together with a concrete example. We'll trace how a SuperFibre 200 Home broadband product flows from the Product Catalog all the way down to network resources, and then follow an order through the end-to-end fulfilment process.

Complete Decomposition Chain

The full decomposition from commercial offer to physical resource follows this chain:

SuperFibre 200 Home — Decomposition Chain
Each layer realises the one above it through the catalog relationship structure

Step-by-Step: SuperFibre 200 Home

1. Product Offering

SuperFibre 200 Home is the offering the customer sees on the website. It is priced at £39.99/month, available for residential customers in FTTH-covered areas, with a 12-month minimum term. It includes a bundled Wi-Fi router.

2. Product Specification

The offering references the SuperFibre 200 Specification: 200 Mbps downstream / 20 Mbps upstream, FTTH technology, /29 IPv4 address block, best-effort QoS. This specification is shared with other offerings (e.g., a business variant priced differently with an SLA).

3. CFS — Broadband Access

The Product Specification realises a Broadband Access CFS. This is the service the customer experiences — they can browse, stream, and connect devices. The CFS has characteristics: connection status (up/down), current sync speed, uptime percentage. SLAs are measured at this layer.

4. RFS — VLAN, BNG Session, IP Allocation

The Broadband Access CFS decomposes into three Resource-Facing Services:

  • VLAN RFS: A customer-specific VLAN on the OLT and aggregation network.
  • BNG Session RFS: A PPPoE or IPoE session on the Broadband Network Gateway.
  • IP Allocation RFS: A public IP address assigned from the operator's pool.

These RFS entities are what the SOM system orchestrates. Each RFS has its own lifecycle — they may be created, modified, or deleted independently.

5. Resources

Each RFS binds to specific resources:

  • VLAN RFS binds to a VLAN ID (e.g., VLAN 1001) on OLT-7 Port 3.
  • BNG Session RFS binds to BNG-4 Interface 2/1/1.
  • IP Allocation RFS binds to an IP address (e.g., 203.0.113.45/29).

The ROM system checks Resource Inventory for availability before committing the order, then instructs the domain controllers to configure the resources.

End-to-End Fulfilment Flow

Here is how the fulfilment process executes when a customer orders SuperFibre 200 Home:

Step 1
Order Capture (CRM/CPQ)

The customer selects SuperFibre 200 Home on the web portal. CPQ validates eligibility (address check for FTTH coverage, credit check), calculates the price, and generates the commercial order.

Step 2
Commercial Order Management (COM)

The COM system receives the order and looks up the Product Offering in the Product Catalog. It identifies the referenced Product Specification and the CFS it realises. COM creates a Product Inventory entry and, if needed, passes control to SOM via a service order request. The COM manages the overall order lifecycle — tracking that all downstream activities complete successfully.

Step 3
Service Order Management (SOM)

SOM receives the service order request for the Broadband Access CFS. It consults the Service Catalog to determine which RFS entities must be created (VLAN, BNG Session, IP Allocation). SOM creates a service order for each RFS and coordinates their execution. It also sets up the CFS instance in Service Inventory.

Step 4
Resource Order Management (ROM)

ROM receives resource orders for each RFS. It validates resource availability against Resource Inventory, then issues configuration commands to the appropriate domain controllers (e.g., NETCONF to the OLT, RADIUS to the BNG, IPAM for address allocation). ROM tracks each resource order to completion.

Step 5
Domain Controllers & Network Activation

Domain controllers execute the actual configuration: the OLT controller provisions VLAN 1001 on Port 3, the BNG controller creates the subscriber session, and the IPAM system allocates the IP address. The network resources are now active.

Step 6
Order Completion & Billing

SOM detects that all RFS orders are complete and updates the CFS instance to "Active". COM detects the service is active, updates the Product Inventory entry, and triggers the billing system to start charging. The customer receives a confirmation that their SuperFibre 200 Home service is now live.

Key insight: At every step, the catalog defines what happens next. The COM knows to create a service order because the Product Specification realises a CFS. The SOM knows to create three RFS orders because the CFS decomposes into three RFS specs. The ROM knows which domain controller to call because the RFS binds to a resource type. The catalogs drive the automation.

Key Takeaways

Key Takeaways

  • The decomposition chain runs: Product Offering → Product Specification → CFS → RFS → Resource.
  • Each layer is defined in its respective catalog (Product, Service, Resource) and references the layer below.
  • The fulfilment flow mirrors the decomposition: COM → SOM → ROM → Domain Controllers.
  • Catalogs drive automation — at each handoff, the catalog tells the system what to do next.
  • Conditional decomposition rules (technology, geography, segment) allow flexible fulfilment without hard-coded logic.
  • This pattern applies to any product — broadband, mobile, leased line, IoT, cloud — with the same layered structure.
