Network Inventory Overview

What network inventory means in telco and why it is the backbone of OSS.

What Is Network Inventory?

Network Inventory is the authoritative system of record for all physical and logical resources that make up a telecommunications network. It answers the question: what do we have, where is it, what state is it in, and how is it connected? Every service that a telco delivers ultimately depends on resources tracked in inventory — from the fibre pair in a cable to the VLAN on a router.

Inventory is the single source of truth that bridges the commercial world of product offerings and the technical world of network configuration. Without accurate inventory, order fulfilment cannot validate resource availability, activation cannot determine where to configure, and assurance cannot correlate faults to affected services.

Physical vs Logical Resources

Inventory resources fall into two fundamental categories:

CharacteristicPhysical ResourcesLogical Resources
DefinitionTangible network assets with a physical locationAbstract constructs that exist within or across physical resources
ExamplesRouters, switches, ports, cables, racks, chassis, cards, patch panels, towers, sheltersVLANs, IP subnets, MPLS LSPs, VRFs, tunnels, circuits, L2/L3 VPNs, IP addresses
LocationGeographic or site-level (building, room, rack, slot)Topological or domain-based (network, overlay, AS)
LifecycleProcure → Install → Commission → Operate → DecommissionDefine → Allocate → Activate → Modify → Release
DependencyStandalone assetsRide on physical resources (a VLAN exists on a port)
Source of truthInventory system, asset management, physical auditsInventory system, network discovery, IPAM/DCIM systems

Resource Inventory Lifecycle

The lifecycle of a resource in inventory follows a structured set of states that reflect its real-world status:

  1. Planned — The resource exists in the design but has not been procured or installed.
  2. Installed — Physical resource is in place but not yet powered or logically configured.
  3. Commissioned — Resource is tested and ready for service activation.
  4. In-Service — Resource is actively carrying customer traffic or supporting services.
  5. Maintenance — Resource is temporarily taken out of service for upgrades or repairs.
  6. Decommissioned — Resource is withdrawn from service and removed from inventory.

This lifecycle must be synchronised with network operations. Inventory should reflect reality — if a technician patches a fibre onto a different port, the inventory record must be updated. Failure to maintain this synchronisation leads to the "inventory drift" problem that plagues many operators.

Why Inventory Is Hard

Network inventory is deceptively complex. Unlike a simple asset register, inventory must model intricate connectivity graphs: a circuit traverses multiple devices, each device has dozens of cards, each card has hundreds of ports, and each port carries nested logical constructs. The cardinality explosion is real. A single large operator may track tens of millions of resource instances across dozens of inventory domains — access, transport, IP/MPLS, mobile core, fixed, and data centre.

Adding to the difficulty, inventory systems must integrate with:

  • Order management (ROM) — to validate resource availability and reserve resources during fulfilment.
  • Activation systems — to update inventory when configuration changes are applied to the network.
  • Service assurance — to correlate alarms and faults to the resources and services affected.
  • Discovery tools — to reconcile inventory records against live network state.
  • Capacity planning — to forecast when resources will be exhausted.

Inventory in TM Forum SID

The TM Forum Information Framework (SID) models resource inventory as a core domain. The key entities include Resource (base class), PhysicalResource, LogicalResource, ResourceRelationship (for connectivity and dependencies), ResourceSpecification (for catalog-driven resource definitions), and ResourceRole (to distinguish how a resource participates in a service). This model is exposed through TMF 639 (Resource Inventory Management API) and TMF 638 (Resource Catalog Management API).

Key Takeaways

  • Network inventory is the authoritative source of truth for physical and logical network resources.
  • Physical resources are tangible assets; logical resources are abstract constructs that ride on top of physical infrastructure.
  • The resource lifecycle spans six states from Planned through to Decommissioned.
  • Inventory must be synchronised with live network state to avoid drift.
  • TM Forum SID provides the canonical model for resource inventory, exposed via TMF 639 and TMF 638 APIs.
